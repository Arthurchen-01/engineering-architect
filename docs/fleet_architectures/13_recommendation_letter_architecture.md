# 📨 推荐信要求数据集与规约驱动治理架构表

> **涵盖工作区**：`<WORKSPACE>/推荐信`（本机工作区，**非独立 GitHub 仓库**；其规约与门禁由本仓库 `engineering-architect` 统管）
>
> **业务定位**：把美国大学「要几封推荐信、谁写、写多长、在哪里填」从各校官网散落的散文，
> 变成一张**可比对、可离线复算、可验收**的结构化表，供顾问在动笔写推荐信之前查证。
> 采集对象为 Common App 学生端与推荐人端表单层，以及非成员校的官方招生站。
>
> **复杂度分级**：**L3**（跨站采集 + 账号池 + 反检测 + 外部依赖不可控）
> **规范文件**：`<WORKSPACE>/.spec/SPEC.md`（人读版）+ `.spec/SPEC.json`（机读版，符合 `SPEC_SCHEMA.json`）

## 四、 历史核心死穴与刚性防御不变量 (Anti-Bug Invariants)

| # | 死穴（已发生） | 刚性不变量（已写进 SPEC 并自动回归） |
| :--- | :--- | :--- |
| 1 | **账不平**：Mid-year 一度写成 `Required 30 / Not required 17`，30+17≠45 | **INV-01 口径守恒**：分档计数必须加总回 45；`tests/test_reclspec_gate.py` 从 CSV **重算**，不信任报告里的数字 |
| 2 | **口径混用**：把「47 所官方站爬取集」当成「45 所成员校」引用 | **INV-02**：52 / 45 / 47 三套集合任何报告必须写明用的是哪一套 |
| 3 | **批次覆盖**：`run_full_collect.py` 硬编码输出到单一 `full_collect.json`，HairfieldRousse49 批次 14 校数据被抹 | **INV-08 批次不覆盖**：每批次独立文件 + 报告用 glob 读全部批次；验收项 H1/H2 防复发 |
| 4 | **结论被推翻却无痕**：早期写「Counselor 推荐信 45/45 强制」，实际是 27/18 | **INV-10 结论可推翻但要留痕**：必须明确写「那条作废」 |
| 5 | **无来源的数字**：US News 名次追不到在线来源 | **INV-06**：追不到就写「未知」；名次一律标注「人工录入、未经在线复核」，改候补池策略 |
| 6 | **缺口无证据**：只写「未采集」，无法判断是页面不存在还是被拦 | **INV-07**：缺口必须附 HTTP 状态码（Georgetown 4 个 URL 全 403；UC 五校区 letters 路径全 404） |
| 7 | **凭据硬编码**：2Captcha 真实 Key 出现在 4 个文件里（含 `GOAL.md`） | **INV-09 凭据不外发**：Key 移入 `local_credentials.json`（600 权限 + gitignore），代码内零字面量；门禁全工作区扫描 |
| 8 | **官方压力**：账号注册可能被判定为滥用 | **INV-03 账号上限与节流**：学生账号 ≤5（实际 3），动作间隔 1.2–3.0 秒随机 |
| 9 | **打码成本失控** | **INV-04**：实测全流程无验证码控件，打码是兜底，花费必须 $0.00 |
| 10 | **解析改动导致重抓**：官网页面会变，重抓既贵又不可复现 | **INV-05 离线可重放**：原文先落盘，`reparse.py` 零外发（门禁静态检查其无网络依赖） |
